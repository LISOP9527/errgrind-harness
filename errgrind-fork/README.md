# ErrGrind Web composition

English | [中文](README.zh.md)

This patch starts the fork's first Web composition and inserts `@errgrind/episode`. The standard preset retains its basic compaction behavior and `/compact` command. The Web UI presents Error, Grill, Teach, and Drill cards, records the first user-sourced input and attachment facts as Error-time Evidence, and supports revision-specific confirmation with `/error-confirm <revision>`. An initial attachment Evidence item uses an empty quote because the image itself is its source. Its eight model tools are `error_draft`, `error_clarify`, `grill_probe`, `grill_conclude`, `teach_step`, `drill_prepare`, `drill_judge`, and `drill_answer_draft`. Teach and Drill responses are interventions and do not become evidence about the original Error; the original Error draft is locked once Teach starts. `/error-status` is disabled in Web. Ordinary assistant text is hidden in the browser.

The default model is `openai-codex/gpt-5.6-sol` at medium reasoning effort; users can select another model in Web. The route uses the existing DSH `llm-pi-ai` and pi-ai provider login. OAuth credentials are stored by the Host credential service, not in this patch; a user must complete sign-in through an authorization surface. An isolated Web run on 2026-09-25 used real Codex to process a math error with two images and ask a clarification question; the full diagnosis chain has not yet been validated with a real model.

The Web composition retains upstream session, attachment, model, and chat infrastructure, as well as the upstream workspace selector and session UI. Original image bytes now require a durable `saveFile` receipt; upload fails if that save fails, and an image in the first Error message cannot open an episode without a receipt. Normalized image refs carry the exact original receipt, and batch validation precedes writes. A real `LocalAttachmentStore` test and an isolated browser replay using two authentic images verify prompt admission, original hashes, and recovery after reload.

Build the source checkout with `corepack pnpm run errgrind:build`, then start the product with `npm run errgrind:start`. This build checks package-level TypeScript references and produces native, Host, Client, and Web artifacts with a bounded Node heap. It skips the root Host/Client TypeScript aggregate projects and the Web TypeScript project; those remain separate gates, and the latter currently reports TS2878. The build records the ErrGrind client profile and emits an ErrGrind browser title, manifest, and icon; the ordinary `build` command retains DSH branding. After a successful ErrGrind product build, `corepack pnpm run errgrind:build:web` updates only the Web shell for local branding changes and leaves no complete client build record. The launcher uses `ERRGRIND_HOME` (default `~/.errgrind`) and selects the Web profile and fork patch. For low-level DSH launcher debugging only, use an isolated `DSH_HOME` with `NODE_USE_ENV_PROXY=1 corepack pnpm dsh --profile web --patch errgrind-fork/web.patch.yml --no-open` from the repository root. These instructions launch the current composition; they do not imply completion or validation of every product flow. Only Core-validated, source-linked observations may become diagnostic Evidence; a chat transcript alone is not a diagnosis.

The ordinary Host aggregate exceeded both 2 GiB and 2.5 GiB Node heap limits on the 3.8 GiB VPS. The bounded ErrGrind build succeeded there with existing incremental TypeScript output and verified a 267-file client artifact record. This record proves the current artifact bytes and public build profile, not that the skipped root type checks passed. A clean-checkout build at the same memory limit still needs validation; package-level build work and tsdown still cover the broad DSH workspace.

On Node 24 hosts that reach the internet through `HTTP_PROXY`/`HTTPS_PROXY`, set `NODE_USE_ENV_PROXY=1` before launching. Otherwise device-code sign-in may appear successful while Node model requests still time out on a direct connection. Restart Web after changing this environment variable.

The current fork-local product contract is in `errgrind-fork/design/product-contract.md`; the [product TODO](todo.md) tracks migration, presentation, and gradual DSH slimming. The [design index](design/README.md) links current rules and research; the [local migration inventory](history/python-product-2026-09-27/inventory.md) preserves the original fork decision and all predecessor design, agent, progress, and prompt sources. Git history records the exact DeepSeek Harness base; the upstream MIT license applies.

## Current milestone

The current slice covers authentic first-input capture with durable `saveFile` image receipts, model-authored description drafting (`error_draft`), Grill questions (`grill_probe`), a provisional conclusion (`grill_conclude`), and human confirmation of the final draft (`/error-confirm`) that completes Grill at the same time. Without confirmation, Grill stays active and may continue clarifying, probing, and revising the description. Teach and independent Drill become available only after that joint completion. The main agent generates an exact 15-field DrillSpec; Core persists it before model I/O. A separate model call receives only that specification and generates the question and reference answer. Failed drafts retry from the saved specification, and the reference answer is admitted only as private durable Judge context. Judgment binds to a persisted user answer. Image answers use a reviewable `drill_answer_draft`; the learner replies `确认` or `修正：...` to complete the response before judgment. An incorrect judgment atomically stores a lineage-bound derived Error snapshot in the source Session. The user can open that snapshot as a separate pending-Grill Session; repeated opens reuse the same Session, which can be reconstructed from its durable log. Initial Error-time Evidence comes from `error-open` source text and attachment facts; clarification and probe response Evidence comes from `user/message` events. A supported diagnosis requires evidence tied to an actual user response to a probe, with quotes matching source text and the current diagnosis round. The `latest-probe-answer` alias resolves to its durable source. Once Teach starts, later answers are excluded from Error-time evidence and the original draft is locked. The Error projection stateVersion is 8; the separate Drill projection is stateVersion 3.

Review model-visible ErrGrind guidance in `errgrind-fork/prompts/system.md` and `errgrind-fork/prompts/tools.json`; edit them and restart Web. The plugin loads tool descriptions from `tools.json`, while executable schemas and validation remain in `packages/core/errgrind-episode/src/index.ts` and `src/drill.ts`. If Web starts outside the repository root, set `ERRGRIND_PROMPT_PATH` to the absolute system prompt path; `tools.json` is loaded from the same directory unless `ERRGRIND_TOOL_PROMPTS_PATH` overrides it.

The `errgrindEpisode` and `errgrindDrill` projections are host-only. The Error projection uses stateVersion 8 and resolves the `latest-probe-answer` alias to its durable source. Replies recorded as user messages while a clarification is pending are indexed as structured Evidence with their source text and images. The Drill projection uses stateVersion 3 and supports an image answer draft through `drill_answer_draft`; the learner replies `确认` or `修正：...` to complete the response before judgment. The browser displays Error, Grill, Teach, and Drill cards while hiding ordinary assistant text; the Session Controller public view filters event fields, keeping private diagnosis data and the Drill answer key in Host context. Drill draft failures and cancellations retain a recoverable pending specification while exposing only a retry status card.

The fork launcher is `npm run errgrind:start`; it uses `ERRGRIND_HOME` (default `~/.errgrind`) and an absolute fork patch, without importing an old database or credentials. The Error sidebar lists fork Sessions by their public Error descriptions and opens each existing investigation; its explicit Drill action queues a request in the selected completed Error's original Session. The keyless browser replay of a simple fraction Error covers description revision and confirmation, Grill question and conclusion, Teach, independent Drill generation and judgment, an image-answer draft and review, opening the derived Error in its own Session, idempotent retry, cold read, reload, and a 390px layout. Drill generation first persists an exact 15-field specification before a separate model call generates the question and answer; retries reuse the saved specification. Full mobile product acceptance and a live-model full chain remain pending; database migration is not implemented. In one real Codex intake run, the second model call reported 11,520 `cacheReadTokens`; one run does not establish a sustained hit rate or cost. MCP support remains pending. The upstream application metadata remains. The Host projects only public Error list fields; private diagnostic state stays on the Host. The old generic Drill option let the model choose one Error, and this fork does not combine multiple Errors into one Drill.
