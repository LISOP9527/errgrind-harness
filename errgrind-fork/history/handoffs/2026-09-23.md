- 产品目标：数学错题的一次连续 Error 调查，Record 与 Grill 融合；用户看到的是一段可修改、可确认的完整 Error 描述。确认真实错误锚点和结束 episode diagnosis 是不同的业务提交点。Teach 在诊断后进行；Drill 是独立练习，答错可产生新 Error。一次诊断不得升级为长期 Pattern。

## 下一步建议（按可验证的竖切片推进）

1. 先把一次 Error 的**原始输入和原始图片**变成可恢复的 ErrGrind 业务锚点：确定附件原件的存储/引用、来源和不可变性，区分 UI 直接输入与宿主转述。避免复制整个 DSH chat transcript 成第二套业务权威；Domain 事件和 DSH Session 的关系必须可审计。处理模型请求失败、中断、重启后继续编辑，以及已确认描述的实质更正。
2. 在同一 episode 中完成受控 Grill：内部保留候选机制、区分性提问、回答出处、不确定诊断和明确的诊断结束条件；公开返回只给可读结果，不泄露内部预测或 variant 答案。Grill 不得在错误锚点未经核对前定案。不要用另一个“Error workflow”或长期 Pattern memory 代替这些业务契约。
3. 做单一 Error 工作区的最小 UI：用户能看到完整描述、修改/确认、继续回答、暂停恢复；图片、长数学文本和手机窄屏可用。移除或封闭 coding 工具、workspace、权限文案时检查**实际执行面**，不只看配置或视觉隐藏。
4. 最后接 Teach/Drill，并为未来 MCP 暴露同一 Core 操作。Drill 要保留 attempt、判分及答错派生 Error 的出处/原子性；Teach/Drill 之后的观察不得回填成 Error-time 因果证据。

### 变更内容概要

1. **图片原件与原字节捕获 (`saveFile` 拦截与 SHA-256 存证)**：
   - 拦截 `AttachmentStore` 的 `saveImage` 与 `saveImages`，在任何图片归一化前先调用 `saveFile` 写入原始原件。
   - 记录原始文件的 SHA-256 哈希、字节大小、媒体类型及文件名。
   - 区分 `direct_user`（用户直接输入）与 `host_relay`（宿主转述）的来源区分及 ID 溯源。
2. **受控 Grill 诊断与诊断账本 (`DiagnosticLedger`)**：
   - 支持多候选假设 (`H1`, `H2`...)、区分性探针 (`P1`, `P2`...) 与结构化证据条目 (`E1`, `E2`...)。
   - 探针区分为推理性提问 (`reasoning_question`) 与变式题 (`variant_problem`)；公开卡片只展示题目/问题，将模型预期观察与变式题标准答案 (`answerKey`) 封闭在探针元数据中，防止泄露。
   - 诊断结论必须在用户通过 `/error-confirm` 确认真实错误描述草稿后方可提交；结论分为 `supported`（需绑定确立机制）与 `undetermined`（需声明剩余不确定性）。
   - 诊断定案后若 Error 描述产生新修订版本，自动标为陈旧待复核 (`stale: true`)。
3. **消除同步事件读取 (`latestTurn` 投影)**：
   - 遵循 `.agents/notes/implemented/architecture/2026-09-09-deprecate-synchronous-session-event-reads.md`，移除了对 `session.snapshotEvents()` 的同步调用。
   - 在 `errgrindEpisode` 投影中处理 `turn/start` 事件，维护 `latestTurn: number`，工具执行时直接从已投影状态读取。
4. **严格代码规范与零警告**：
   - 消除所有非空断言 (`!`)、多余类型断言 (`as ...`)、`any`/`unknown` 转换。
