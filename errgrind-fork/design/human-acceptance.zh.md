# ErrGrind 人工验收计划

无密钥流程和传输检查通过后，先验收诊断与 Drill；完成可逆的 Web 瘦身后，
再验收手机端和产品界面。这两次验收均安排在旧数据导入、MCP 接入和发布之前。
测试者使用全新的 `ERRGRIND_HOME`，启动时设置两个中转 API key 环境变量，并在表格副本中记录
观察结果。不要把旧数据库、附件或凭据复制到 fork。

## 1. 诊断质量

使用一条真实数学错题以及题目和作答过程。检查图像事实是否忠实、确认前能否
修改描述，以及探针能否区分至少两个合理机制。分别尝试没有证据的结论、
undetermined 结论和共同确认，记录界面是否清楚表达不确定性与下一步动作。

## 2. 干预与 Drill

进入 Teach，再从已确认机制准备 Drill。检查题目是否自洽，且与原题有实质
差异，包括使用等价数学方法时。提交推理不完整但结果正确的答案和实际错误的
答案。确认判分记录完整，数学正确性与机制证据分开处理，错误答案只产生一个
带 lineage 的待 Grill Error。图片作答必须先修改转写草稿并确认；确认前不得
判分。

## 3. 恢复与隐私

中断出题、刷新并重试，再做一次冷启动。诊断版本改变后也要重试。保存的规格
必须按原字段恢复，过期规格必须清楚拒绝。捕获浏览器 history、search、reconnect
和 WebSocket payload，确认 Drill 私有答案、探针预测、工具参数和附件存储引用
均不会出现。

## 4. 产品表面

在 390px 视口完成包含长公式、长答案和脏 composer 输入的完整流程。检查保留的
会话导航、模型选择、图片上传、错误恢复，以及上游 onboarding 或无关工具设置
是否已隐藏。记录屏幕尺寸和可复现步骤。

再建立第二条 Error，重启后通过 Error 历史找回并打开两条记录。未完成的 Error
不应提供 Drill 操作；对已完成的 Error 点击定向练习后，应在独立的 Drill 会话中答题判分；判分卡只显示对错。
答对则该会话从历史中彻底消失（归档且不留痕）；答错则物化一条待 Grill 的衍生 Error，并在学习者离开练习会话后同样归档消失。没有缓存 Error 分类的旧会话也应仍可打开。
