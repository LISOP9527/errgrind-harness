# ErrGrind human acceptance plan

Run the diagnostic and Drill cases after the keyless workflow and transport
checks pass; run the mobile and product-surface cases after the reversible Web
slimming pass. Both checkpoints precede old-data import, MCP integration, and
release. A human tester supplies a fresh `ERRGRIND_HOME`, launches with both relay
API key environment variables set, and records observations in a copy of this table. Do not copy an old
database, attachments, or credentials into the fork.

## 1. Diagnostic quality

Use one real mathematics Error with the original problem and the learner's
working. Check that image facts remain faithful, a description can be corrected
before confirmation, and a probe distinguishes at least two plausible
mechanisms. Try an unsupported conclusion, an undetermined conclusion, and a
joint confirmation. Record whether the UI makes the uncertainty and the next
action understandable.

## 2. Intervention and Drill

Continue into Teach, then prepare a Drill from the confirmed mechanism. Check
that the question is self-contained and meaningfully different from the
original, including when equivalent mathematical methods are used. Submit a
correct answer with incomplete reasoning and an actually wrong answer. Verify
that mathematical correctness is judged separately from mechanism evidence,
that every attempt is retained, and that a wrong attempt opens one lineage-bound
pending Error. For an image answer, edit the transcription before confirming
it; the Judge must not run before confirmation.

## 3. Recovery and privacy

Interrupt draft generation, reload, and retry. Repeat after a cold restart and
after the diagnosis revision changes. The saved specification must resume with
the same fields, while a stale specification must be rejected clearly. Capture
browser history, search, reconnect, and WebSocket payloads and confirm that
private Drill answer keys, probe predictions, tool arguments, and attachment
storage references never appear.

## 4. Product surface

Run the complete flow at a 390px viewport with a long formula, long answer, and
dirty composer input. Check the retained session navigation, model selector,
image upload, error recovery, and the absence of upstream onboarding or
irrelevant tool settings. Record any layout, wording, or focus failures with a
screen size and reproducible step.

Create a second Error, then use the Error history to find and reopen each one
after a restart. The unfinished Error must not offer Drill. Select the
completed Error's Practice action and confirm that the question and attempt
run in a dedicated Drill Session; the verdict shows correctness only. A
correct verdict removes it from history entirely, while a wrong one
materializes a derived pending-Grill Error and removes the practice Session
once the learner leaves it.
Check that an old Session without a cached Error classification is still openable.
